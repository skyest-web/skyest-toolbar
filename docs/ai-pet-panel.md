## 3. 情绪协议

模型每次回复**开头**输出一个白名单标签，正文随后：

```
[开心] 今天天气不错呀，你回来啦。
```

白名单 6 个，**不多做**（每个情绪 = 一套眼睛+嘴巴形状，素材成本线性增长）：

| 标签 | 触发语义 | 宠物表现 |
|---|---|---|
| `[开心]` | 好消息、被夸、闲聊愉快 | 眼睛弯成弧、跳一下 |
| `[平静]` | 默认、事实性回答 | 常规呼吸 |
| `[好奇]` | 反问、追问、感兴趣 | 头歪、眼睛放大 |
| `[困]` | 深夜、无聊、长回答后 | 眼睛半闭、Zzz |
| `[生气]` | 被冒犯、拒绝 | 眉毛倒竖、腮帮鼓 |
| `[难过]` | 道歉、坏消息 | 眼睛下垂、滴汗 |

规则：
- 只匹配**开头**、**第一个**、**严格白名单**的标签；不匹配就当普通正文显示（最坏是用户看到一个方括号，不会崩、不会吞字）。
- 未知情绪名 → 回落 `[平静]`。
- `[生气]`/`[难过]` 只是表情，**不影响回复内容本身**，避免模型真的变冷淡。

## 4. 剥离点：为什么在主进程，不在渲染层

### 4.1 推荐：主进程 `finish()` 剥离 + 渲染层临时遮蔽（同一正则）

- 主进程 [src/main/services/ai.js:247](file:///C:/SyncData/project/skyest-toolbar/src/main/services/ai.js#L247) 的 `finish()` 里，把标签从 `content` 剥掉，存成 `message.emotion`。
- 渲染层对 **live 气泡**做同样的前缀剥离（流式期间标签可能刚到达，还没走到 `finish()`）。
- 两处共用一条导出的 `EMOTION_RE`，避免规则漂移。

### 4.2 决定性理由：回传给模型的历史必须干净

`contextFor()` 会把 `messages` 拼回请求体。如果标签留在 `content` 里，模型第二轮会看到"我上一轮说过 `[开心]`"，于是**模仿并累积**（实测这类前缀协议一旦进历史，几轮后会出现两个标签、或把标签写进句子中间）。剥离在落库前做，历史永远干净，协议就稳定。

### 4.3 放弃项

- **只在渲染层剥离** → 历史污染，几轮后行为漂移。放弃。
- **让模型用 JSON 返回 `{emotion, text}`** → 流式下要处理半截 JSON，且 DeepSeek 对严格 JSON 的遵循度不如一个方括号标签，失败时整条回复不可读。放弃。
- **不做情绪，只有固定表情** → 实现最省，但"宠物"就退化成一张会动的贴纸，达不到你要的效果。放弃。

## 5. 素材形态：内联 SVG + CSS 关键帧

### 推荐：一只矢量团子，表情靠切换 `<g>` 的 class

- 身体 = 1 个可形变的 blob path；眼睛/嘴/眉毛 = 各自独立的 `<g>`，切换 `data-mood` 即换形状。
- 动画只用 `transform` 和 `opacity`（不碰 `width/top`），常驻全屏的工具栏不能因为一个宠物涨 CPU。
- 待机 = 呼吸缩放 + 随机眨眼（`animation-delay` 随机化，避免机械感）。
- 尺寸自适应格子，**2x / 1.5x / 1x 三种 DPI 下发虚**是位图素材的硬伤，矢量天然免疫（本机三屏正好是这三种缩放）。

### 放弃项

| 方案 | 放弃原因 |
|---|---|
| 精灵图帧动画（sprite sheet + `animation-timing-function: steps()`） | 需要位图素材；本机三种 DPI 缩放会糊；每个情绪 × 每个动作 = 一整套帧，素材量爆炸 |
| Lottie / GSAP / pixi | 破零依赖 |
| Live2D | 要运行时 + 模型文件，且必须授权，不现实 |
| GIF | 不能换色、不能分层控制表情、体积大 |

### 形象已定：猫团子（团子身形 + 一对猫耳，不做尾巴和四肢）

2026-10-27 定稿。取舍过程：

- **纯团子**（否）：素材最省，但一个圆 blob 配两眼一嘴辨识度太低，和通用加载动画无异，容易第三天就看腻。
- **正经猫**（否）：耳朵、尾巴、四肢都得有，且耳朵尾巴本身要随情绪动（竖耳/飞机耳/炸毛），额外三套形状，素材量约三倍。
- **猫团子**（选）：身体仍是一个可形变 blob，情绪仍只靠眼+嘴+眉三件；两只三角耳是**贴在头上的静态形状**，素材成本基本不动，辨识度却立刻不一样。

**唯一为它多花的预算**：耳朵做**两个状态**而非每情绪一套 —— 正常 / 飞机耳（`[生气]`、`[难过]` 时压平）。一个 class 切换，几乎零成本，而"飞机耳"是猫最有杀伤力的表情，比调眉毛有效得多。

**明确接受的代价**：不做尾巴和四肢，所以没有"摇尾巴""伸懒腰"这类动作，情绪表达上限低于真猫。常驻在 400px 竖条里的东西，动得越少越不烦人，这个交换划算。

等 M2 跑通想换形象，只需替换 SVG，代码不动。

## 6. 界面结构

```
┌─────────────────────────┐
│ AI 伙伴   deepseek-chat  清空 设置 │   ← 头部保留，标题改名；设置入口在头部
├─────────────────────────┤
│      ╭──────────────╮   │
│      │ 漫画泡：当前回复 │   │   ← 只显示最近一条 assistant
│      ╰───╮          │   │
│          ●‿●  ← 宠物（SVG，居中，约 40% 高）
│  ───────────────────────
│  你：今天几号            │   ← 上一条用户输入，小字
│  ▸ 查看完整对话 (12)      │   ← <details>，展开是原来的滚动列表
└─────────────────────────┘
        ↓ 平时不存在，打字或录音时才浮出、盖在面板底部
      ╭───────────────────────╮
      │ [ 输入框        ] 🎤 发送 │   ← .ai-compose 浮层
      ╰───────────────────────╯
```

要点：
- **完整历史不删，折叠**。原来的 `.ai-list` + `stick`/`jump`/`scrollToEnd` 那套滚动逻辑整体搬进 `<details>`，展开照用。放弃"彻底去掉历史"：出问题看不见上下文，而且白扔已有代码。
- 输入区原来是常驻底栏，现在是**浮层**：平时面板底部只剩宠物，单击宠物或点头部「打字」把它浮出来——**点出来只是把条子摆好，打还是说由他自己选**，发出去/按 Esc/点别处就收起。
- 错误态：宠物头顶一片小乌云 + 原来的「重试上一条」按钮（`errorBubble` 复用）。
- 未配密钥：宠物变灰、举一块小牌子「先去设置填密钥 →」，替代现在的纯文字引导。

## 7. 交互

| 动作 | 反应 |
|---|---|
| 单击宠物 | **浮出输入条**，不开麦：打字就直接写，说话就点条上的麦克风按钮。只有在**已经在录音**时这一击才生效=「说完了」停麦（识别出的最终文本按 `voice.autoSend` 决定直接发送还是留在浮层里改）。同时本地播一条短反应，不请求 API。**以前是单击即开麦，他要求改成自己选** |
| 双击宠物 | 打开 **DeepSeek Harness 窗口**（官方 `dsh` 的 Web UI，装在独立系统窗口里，能拖到别的屏幕，见 [docs/dsh-panel.md](file:///C:/SyncData/project/skyest-toolbar/docs/dsh-panel.md)）。已经开着就只是把它提到前面并抢焦点。打字入口搬到了头部的「打字」按钮，设置入口在头部的「设置」按钮 |
| 头部「Harness」按钮 | 开/关同一个窗口；标签实时显示版本与端口，运行中且窗口开着时带 `▣`。窗口右上 × 只收起，不退 dsh 子进程 |
| 右键宠物 | 打断：停掉正在朗读的话，流式回复中顺带 `abort()` |
| 流式回复中单击宠物 | 照样只浮输入条；要打断就用右键，要说话就点麦克风（点麦克风本身就会 `stopSpeaking()`） |
| 悬停宠物 | 轻微跟随视线的眨眼，纯 CSS —— **未实现** |

单击延后 260ms 触发，给双击让位（浏览器连发 click/click/dblclick，两个定时器都会被 dblclick 清掉）。

不做拖拽 —— 那是重的那层的能力，这里做了会误导。

## 11. 风险

| 风险 | 应对 |
|---|---|
| 模型不输出标签 / 把标签写进句子 | 只剥开头 + 严格白名单；失败时最坏显示一个方括号，功能不崩 |
| `deepseek-reasoner` 的 `reasoning_content` 里混进标签 | 只处理 `content`，`reasoning` 原样展示在「思考过程」折叠区 |
| 常驻动画抬高 CPU | 只用 `transform`/`opacity`；`motion:'off'` 一键全静；实测见下方 §11b |
| 每轮多耗 system prompt token | 约定文本约 60 字，可忽略；`emotion:false` 直接省掉 |
| 宠物组件抛异常带崩 dock（同类事故已发生一次） | `update()` 内部 try/catch 自封闭，异常只降级成 `calm` |
| try/catch 把渲染错误吞成"表情不对"，肉眼查不到 | 已踩过：`build()` 里 `this.bubble = <div>` 覆盖了同名方法 `bubble(message)`，`render()` 后半段静默抛错、catch 又把宠物按回 `calm`，看起来像情绪协议没生效。排查靠 CDP（`--remote-debugging-port` + `Runtime.evaluate`）直接读 `data-mood` 与 `TB.app.state`，别猜截图 |

### 11b. M2 实测（本机 3 屏、工具栏在 #0 @2x、18 核）

| 配置 | 工具栏 4 个进程合计 CPU |
|---|---|
| `motion:'off'`（基准，只剩时钟/指标刷新） | ~7.6% 单核 |
| `motion:'full'`（待机 + 眨眼，改造前） | ~38% 单核 |
| `motion:'full'`（待机移到宿主 div + 眨眼改定时一次性） | ~19% 单核 |

即宠物常驻多耗 **约 12% 单核 ≈ 18 核机器的 0.7%**。两处改造是省下来的关键：SVG 内部元素的 infinite 动画每帧重新栅格化矢量，而 `scale` 让 Chromium 无法只拉伸纹理。
结论：`full` 可以常驻，但**只有 `off` 真正省 CPU**——`calm` 只是变慢，帧数一样，所以 §12 Q4 不再是性能问题，纯审美问题。
